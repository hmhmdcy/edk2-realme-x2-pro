## 控制延迟

复用306的标准V4L2 SOF测量方法，不在测量profile中填延迟，也不开启AE/AWB。每摄120帧，六次单控切换：四次曝光、两次模拟增益，覆盖增加与降低。主摄650↔1600行、gain code64↔128；前摄768↔1800行、code512↔768。实际初始值在SOF0读回，109个SOF连续且无待处理事件积压。

主／前摄各30个有效响应域（BHIST＋四个图像Y分区×六次切换），首次变化及三帧平台均为写入SOF＋2。共60个响应域一致，不再根据其它传感器猜测延迟。[测量结果](delay-r1-validation.json)。仅覆盖当前模式、正常及时回调及这些曝光／增益范围；未证明所有模式、极限增益、严重回调延迟或逐像素锁存。

主摄帧周期33271.463µs，与现有17824行长／1.92GHz阵列率／3584帧长比例相符。前摄33333.365µs；该模式最小帧长2124、当前4250，不能用最小值代替当前30fps时序。

据此在两个模组的用户空间模式配置填写曝光／增益延迟2，沿用既有CameraSensorHelper、DelayedControls和libipa AGC／AwbGrey后端。未修改公共传感器属性、内核驱动或板级配置。
