2026-10-19。已在硬件IPA／pipeline接入运行中的AwbEnable和ColourGains请求；四摄当前模式完成自动→手动→再次手动→自动切换。修正后394帧、12次控制在各自请求图像的同一SOF生效，64个可辨图像颜色响应域同帧变化。产品仍RAW＋CPU ISP，完整校准和适配目标active。

## 实现与来源

依据SDK本地control_ids_core.yaml及[libcamera控制文档](https://docs.libcamera.org/master/internal-api/namespacelibcamera_1_1controls.html)：AWB关闭时应用手动ColourGains；开启时忽略请求中的手动增益。本实现支持AwbEnable／ColourGains，尚未补齐色温、CCM及全部AWB模式，未伪造色温校准曲线。

请求先做无副作用校验，只有图像缓冲成功入队才保留控制；在途统计和参数确认完成后按顺序处理。手动和自动更新共用revision及参数缓冲，没有另造应用专用ISP接口。

IPA的参数历史保存每个确认SOF对应的AWB模式和量化增益，旧图像保留旧状态。关闭AWB且未给新增益时保留最后生效参数；手动期间不产生自动WB更新，重新开启会重置算法稳定计数。冻结保留原参数源值，避免将量化比值再次编码造成漂移。

pipeline根据已完成图像建立请求序号与SOF的映射，在目标帧前一个SOF提交参数，避免提前改变仍在队列中的其它请求图像。映射变化时拒绝后续运行中ISP请求并要求重开；图像丢帧、严重IPC积压／饥饿及自动恢复仍待扩展。当前不把正常连续流的实测推广到这些异常路径。

内核、DT、板级供电及传感器驱动均未改。变化在通用用户空间IPA／pipeline／代理接口，四个模组沿用310已测模式profile。[相对308的补丁](runtime-controls.patch)、[当前源码及候选标识](source-state.json)、[构建](build-validation.json)。

实际AArch64 IPA DSO模型检查包含三帧参数确认延迟、确认前旧模式、手动关闭／手动增益／重新开启、开启时忽略增益、非法值拒绝和重开。该结果不代替物理时序或色准校准。[IPA检查](ipa-contract-validation.json)。
