# 229：白天前摄真实颜色信息已确认

后续[230真正树内加载与五SSC再验已通过](../kernel230/README.md)，当前taint0；本页保留本阶段当时状态。

2026-10-16，用户说明“天亮了，摄像头应该能拍到颜色了”。在新启动228、r13/config-r8、IMX471 e49/CAMSS fae1下，使用真实场景、sensor/CSID图案均0，先做4MP RAW/RGB各6帧，再做32帧RGB通道统计。全部像素只在RAM读取，未保存或展示场景照片，没有闪光或外部照明。

RAW2304×1728六帧范围约63–1018，均值96.88–98.88、标准差36.89–39.05，存在明显空间变化；[RAW收据](raw-daylight-baseline-validation.json)。夜间223约62–133、标准差2.66，仅用于说明两批样本不同；它们不是同曝光/同软件条件的严格光量对照。

RGB2296×1728的32帧均有效且非全零，已观察到三个通道差异。[32帧原始统计](daylight-colour-native-validation.json)、[汇总](daylight-colour-validation.json)。末帧通道均值按R/G/B约71.11/72.45/70.69，约12.86%像素满足max通道≥24且通道差≥12/255；任一通道≥250的像素约0.074%。这说明输出不只是全零或强制复制同一灰度通道，不能据此验收真实颜色准确性。

RGB888在此小端平台的内存字节顺序为B/G/R，核对来源是当前固定libcamera的formats.yaml映射及内核drm_fourcc.h。探针原始字段保持`byte_channel_*_012`，颜色名称由核对后的顺序解释。不能把格式名直接理解成内存R/G/B。

32帧内曝光元数据为33192µs，增益1.0→1.573，均值24.19→71.42，末段仍在调增益，**未宣称AE已经收敛**。整体通道均值接近也不能排除局部偏色、CFA映射或白平衡误差；需要有参照的场景，继续确认真实颜色/几何/标定。

新统计探针只编译一个客户端，未重建SDK或更换库；[构建](colour-probe-build-validation.json)。已检查每帧FrameSuccess、DMA读同步、完整活动像素并排除RGB行padding，记录曝光/增益。测试后控制、格式和媒体链路恢复，相机设备休眠，五类fault增量0。FastRPC仍为228已验证外建模块，4096/O属于先前已分类标记，树内默认2abde待干净启动；详见[228](../kernel228/README.md)。
