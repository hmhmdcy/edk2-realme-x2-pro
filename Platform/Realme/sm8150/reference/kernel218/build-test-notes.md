# 原生 Quad Bayer CPU 候选的验证边界

阶段218，当前仍是216驱动和214完整r5软件包。217内核/DTB候选未安装；218只在独立目录构建，不修改214源码、构建目录和已签名产物。

## 相关机型与接口依据

- [一加6T IMX371的libcamera补丁](https://patchwork.libcamera.org/patch/28095/)用2×2同色单元平均解决颜色问题，宽高各折半，并拒绝CPU回退；评审中也有一加6使用者反馈。它证明了可借鉴的Quad CFA处理路径，不能作为原生16MP处理验收。
- [补丁作者对模式接口的后续追问](https://lists.libcamera.org/pipermail/libcamera-devel/2026-September/061905.html)区分了传感器物理CFA与当前模式输出CFA。本次仍将内核与用户态之间的模式CFA描述列为待解决项；没有根据一次头文件搜索断言整个内核没有相关API。
- [内核RAW10 packed说明](https://docs.kernel.org/5.16/userspace-api/media/v4l/pixfmt-srggb10p.html)规定四个采样点用五字节存放，低两位在第五字节；普通Bayer格式同时描述交替的单像素颜色排列。不能仅凭相同打包方式就把Quad CFA称为普通Bayer。
- [UNIT_CELL_SIZE定义](https://docs.kernel.org/5.19/userspace-api/media/v4l/ext-ctrls-image-source.html)是以纳米为单位的物理像素大小，且不反映硬件binning；不能填入2×2并用作Quad模式标识。
- 本机4608×3456模式与2304×1728的两种bin模式，以217独立解码的原厂模块BIN和厂商解析器XML为依据，不复制一加/笔记本的镜头校准。

## 本次实现

`native_quad_bayer.h`对每个物理采样位置产生一个RGB10像素，保持该位置已测得的颜色值，插值另外两个颜色。输入与输出宽高相同；没有2×2合并、缩小再放大。缺失R/B按最近有效同色坐标作双线性插值，缺失G合并水平与垂直的同色插值。图像边缘采用最近有效同色样本，不把其他颜色的边缘像素当成目标颜色。RAW10先按行解包，五行缓存由各工作线程独占。

这是可核验的基础双线性算法，未声称达到原厂重马赛克、去噪、锐化或镜头标定质量。

libcamera候选按IMX471、4608×3456和显式`software_isp.experimental_imx471_native_quad: true`共同启用，默认关闭。这是针对本机已核对模式的临时接口，不能代替通用CFA ABI。完整模式拒绝缩半输出及EGL处理；普通模式继续走原CPU路径。统计计算允许对同色单元采样，但不改变像素输出尺寸。启用实验时输出只用system heap，避免优先选择CMA；FastRPC专用池不用作图像缓冲。

## 已完成的独立验证

- 宿主ASan/UBSan和警告视为错误构建：400组、63,360像素，四种排列、最小4×4、边缘、带毒填充、随机值、线性颜色平面、低两位、单像素脉冲以及非四行对齐分段，独立扫描坐标的浮点参考实现逐点比较通过。
- 手机普通用户运行相同测试，以及三帧完整4608×3456合成RAW；每帧输出47,775,744字节RGB。四线程约136.680/139.105/136.324 ms；这不是实时30fps或实拍验收。测试峰值RSS包含合成RAW参考数组，不能直接当作生产ISP占用。
- 手机system heap同时分配四个完整RAW10和四个完整RGBA缓冲，共334,430,208字节，逐个映射和DMA同步通过，全部关闭；测试前后CmaFree相同。仅验证分配与CPU访问，没有据此声称完整尺寸CAMSS导入、传感器出流或GPU通过。
- 上述测试没有启动摄像头、显示/保存房间画面或使用闪光灯，taint与五类故障增量均为0。

## 构建与后续验收

初次广泛目标构建主动中止，保留已编译对象，改为核心库与相关测试。r2在警告视为错误的编译中发现成员初始化顺序错误，修正后r3构建通过；相关四项Meson测试均通过，不声称运行了整个上游测试套件。

CPU类实机测试使用真实DMA heap与libcamera FrameBuffer，50组合成输入、780,337,408个像素检查通过，覆盖四种CFA、六种RGB布局、非单位颜色矩阵、alpha、输出边界与有效字节、统计结果、完整→普通→完整配置切换；另外验证默认不启用完整模式。第一轮脚本错误要求无动态库依赖的头文件单测必须加载libcamera，尚未执行测试就停止；修正规则并保留原日志后完成测试。

隔离候选另完成当前1928模式的真实暗场RAW六帧和CSID数字白RGB六帧回归。暗场均值约64、stddev0.439–0.475、逐帧变化32.85%–36.14%；白RGB首帧起每字节254。控制/link恢复、相机休眠、taint及五fault增量0。未保存或展示场景图像。

初次白RGB回归的配置前检验失败也保留：独立Meson构建使用默认`/usr/local`前缀，没有读取产品`/etc/libcamera`配置，选到了EGL/XRGB8888，而探针要求CPU/RGB888；取流前即停止。r2显式选择与产品配置逐字一致的私有XDG副本后通过。这个失败不是暗场黑帧，也不能根据原脚本仅核对文件哈希就声称CPU配置被加载。新库与原r5内嵌IPA公钥源码一致，回归使用原r5已签名IPA。

完整传感器RAW、模式选择/COMPOSE语义、曝光/帧时序、标准控制、画质、默认客户端和完整软件包的回归仍不能由本次合成测试替代。几何问题见[接口审计](geometry-interface-audit.md)。
