## 失败与修正过程


后摄IMX319在标准GStreamer设备提供器、默认共享缓冲池、无应用复制开关下能够预览并保存1600×1200 JPEG。用户确认镜头朝向光线较弱的电脑桌；私人样本有可辨认场景细节但整体偏暗，不能以遮挡或纯黑解释。低照度曝光、增益与调校仍待处理，样本不公开。

连续拍照扩展测试发现264验收范围外的问题：run1的329次保留检查中1次内容变化，并出现1条未回收缓冲错误；run6在三次快门全部成功的同时，332次检查中有2次内容变化。PTS本身保持不变。两轮按失败保存。run2—5各自通过不能覆盖这些失败。检查只哈希每帧前65536字节，并非整帧证明。每轮正常释放后PM休眠、MCLK关闭、无新增fault且taint=0。

GStreamer候选增加独立映射的Busy所有权，不增加像素复制或清零计数。v2在run7—9通过9张照片/1040次保留检查；多客户端测试6000091有一次长客户端无结果，未保存该子进程退出码，不能直接认定其信号或原因。其余崩溃恢复、原生并用、单次/三轮/六轮关闭分别通过，但不能覆盖这次失败。

可控的真实ARM64 GStreamer回收测试发现，v2新增的临时父缓冲引用会在原dispose回调尚未结束时释放对象；64轮无临时引用对照通过，负向对照被检出。v3撤去这段新增操作，恢复r1原退出回调，但run10仍在三张照片成功时检出1次内容变化。因此GStreamer候选尚不能部署。

公共SPA的`port_use_buffers`在清除旧Busy绑定后会沿用原图像缓冲。新的SPA候选尝试重新分配图像缓冲；源码编译通过，run11确实触发5次重新分配，但原系统GStreamer下仍有4次内容变化，测试失败。不能称单独SPA修改已解决问题。后续组合验收已通过；这里保留单项失败，不能把单独修改当作充分修复。私人覆盖已撤。

第一版候选的模拟映射测试未覆盖导入块无默认映射，未部署。后续公共映射查询接口与260个真实导入/非零偏移/退役/失败路径场景通过，FD增长0；删除所有权增量的负向对照失败。但这不能代替完整管线验收。所有失败候选、源补丁及测试结果保留。

生产测试不在libcamera背后恢复media链接、格式或AE。trace与临时日志级别按实际前值清理；已有一次性上下文不可盲目重跑。私人资料位于`E:/edk2-samurai-out/kernel265`及手机`/var/lib/samurai/k265-*`，运输复用260严格原主机密钥并核对当前启动。

待办：内核方向/旋转/裁剪元数据、后摄低照度与颜色、GUI选择/切换、录像/长稳和S5K3M5/GW1等后摄。既有CPU显示配置保留，默认GPU及GPU ISP退出告警未修；完整相机适配目标保持active。
