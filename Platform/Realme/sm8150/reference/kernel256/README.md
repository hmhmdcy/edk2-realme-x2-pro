## 对PGA、时钟及旧判据的修正

这次同一原厂系统启动、同一HAL中，PGA由此前室内采集的−6变成本轮+2；没有直接设置PGA、NV或校准。这是比第三方Android历史变化更直接的原厂证据：**−6不是原厂系统始终固定的PGA报告值。** 但增益算法、物理寄存器和配置默认值仍未解出，不把它等同于灵敏度变化的实测dB，也不能将PGA变化单独认定为定位恢复原因。

QMI频率估计来源依然是1，原厂此次成功定位时并未切成另一来源；此前source1本身不能作为故障判据。不确定度从255室内的94 m/s变为本轮数m/s，是伴随持续跟踪的运行指标变化，不是测得实际载波偏差，也不证明物理XO/PLL已经逐项验收。重置计数首批8份为61，随后2408份为64，起始会话切换后保持64；不将计数变化自动等同于系统或modem重启。

GPS L1 C/A的AGC指标0.14—0.61 dB，BP指标58 dB；255室内对应BP常为65—66 dB。该接口是运行指标，没有本机干扰阈值或天线输入功率标定，不能由这组数字单独宣布干扰源、噪声底或损坏器件。[PGA与频率指标](pga-clock-validation.json)

另外，成功定位时GPS测量的`lock_point`上报位依然全部为假，而TRACK、fresh、位边沿和成功位置回包已经成立。**不能再把单独未置位的lock_point当成无法TRACK/定位的充分判据。** 253/254旧记录中的该位数值保留，但解释须结合本轮成功对照。[原始测量汇总](measurements-validation.json)

## Linux比较范围与后续依据

此次证明这台手机在原厂、室外、拔掉USB且保持Wi-Fi的组合条件下，GNSS接收、持续测量和定位输出链能够工作。它削弱了“持续性硬件完全失效”这一解释，但没有定位室内失败的具体环节。

从室内USB采集到此次室外无线采集，同时改变了位置、USB连接及时间等条件；没有做单变量往返对照，因此不把改善唯一归因于室外信号，也不排除USB相关影响。没有复现冷启动、长稳、恶劣环境或标定精度。

Linux的client1完整5 MiB连续内存/SCM provider差异仍开放；本轮没有证明它与定位的因果关系。现在已有可定位的原厂原始测量基线，后续Linux应在相近室外、断开USB及一致采集方法下比较，而不能继续只将旧室内SEARCH结果与此次室外成功结果直接对比。
