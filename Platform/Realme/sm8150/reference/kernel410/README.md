## 数值实现与证据边界

接口显式接收 DRC／暗部增益与已选区域的五个参数，计算四个膝点、六个系数、LTM／GTM 百分比和混合量。量化增益用1.03步长与94索引上限；暗部比例限于1至16，LTM百分比按8倍目标增益上限调整。近 unity 的两种比较阈值与暗增益计算顺序保留，不能合并精度不同的运算。

**膝点生成与百分比策略仅对照固定源码，尚未执行本机 HAL 的膝点生成函数。** 增益采样则执行本机原 HAL `0x3c6328`：它是64段／65节点的特化函数，Q因子10由 W5 传入；混合量另对照 `0x3626f8…0x36273c`。累计1391456条目标指令、84370次 powf provider；powf采用主机 libm，未声称执行原 Bionic 数学库。固定源码与 HAL 的有限采样值、混合量均零字节差异。

[TMC检查](tmc-validation.json)共1301项：18个真实区域乘10种 DRC 增益、6种暗增益得到1080项，另有200项合成和21项边界；区域是真实调校，动态增益网格是测试输入，并非现场 AEC 轨迹。附加33项非法输入。主机 ASan／UBSan与 AArch64 SDK／QEMU 各453560字节零差，启用 `-ffp-contract=fast` 仍保持；输入与失败输出保持。

41项退化输入使原厂采样产生非有限结果，公共接口拒绝继续输出；3项归一化端点为零的输入也明确拒绝，即使百分比为零时原厂未验证函数可因 NaN 的零次幂得到有限 unity。私有原始参考结果与有边界检查的 API 参考分开保存，未通过修改原始结果掩盖数值差异。

[初始 ABI 夹具失败](model-r1-validation.json)保留：首调用输出已零差，但夹具误要求源码 BOOL 返回1；实际特化函数不设置 W0，调用者也不使用它。修正为检查结束地址、输出与保护区，原指令不变。[首次数值比较失败](tmc-r1-validation.json)也保留：两个架构各261字节差异集中在零端点、零百分比一项，来自上述接口拒绝规则；修正参考的有效域映射，原始未检查函数输出仍单独保留。

## 与底层编码器的连接

[链路检查](chain-validation.json)实际组合 TMC10→65点 Q10 增益→409原 HAL ADRC转换／混合→源码 LUT packer，再对照公共实现及维护树原生编码器。1301项中1254项成功、47项拒绝；其中两项膝点退化虽产生有限采样，首增益小于 unity，下游按既有契约拒绝，没有夹到 unity 隐藏边界。

实际 ADRC 目标段另执行12323438条指令，唯一 provider 为1254次 memcpy。两架构均通过；1254份 typed 请求的 curve／scale 共642048字节与参考零差。qtech GW1 基础表仅为未绑定供应商数值夹具。其它 IQ／LUT 填零只验证这条数值链路，关闭的原厂根没有激活；原 HAL 最终 LUT packer仍未执行，不能当作完整原厂流水线或硬件提交。
