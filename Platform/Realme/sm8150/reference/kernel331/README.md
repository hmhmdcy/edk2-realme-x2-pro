2026-10-20。已提取通用C++17二维参考点校准、光源区间分类、色温及有符号轨迹距离计算，[源码](libipa/awb_colour_temperature.cpp)。主机与AArch64对照本机原厂指令结果通过。尚未接入IPA的自动估计；330手动色温候选与系统部署保持，完整goal active。

此前未解析的间接调用已由构造器和实际工厂调用链确认：0x81b8构造流程在0x8228最终写入vptr=0x5ecb8，+32为0x8380、+160为GetCCTFromGain0x9d70。0x25fa0工厂构造vptr=0x5f750的对象，调用方0x360b8～360f8把它交给0x8368写入主对象；该对象+24指向0x264c0。0x9d70→0x8380→0x264c0不是此前基于表中相邻函数位置的猜测。

反向估计使用**refPtV1参考点**，与330正向查表的MWBGainV1数据不同，不能简单互换。工厂配置路径0x25da0～25ef0逐通道将参考点乘329的unit/golden因子，结果由主对象0x91e处送入估计器。十组点只使用实际有效槽位，refPt后五对未用零不参与，也不修补。

估计器沿参考轨迹构造垂直边界，以二维R/G、B/G比值判定区间；由与两端的平方距离求投影权重，再在线性Kelvin上插值，并输出有符号距离和光源索引。复用原厂跳过部分荧光点的连接、重复边界、两端夹取及分类语义；两端夹取的光源标签分别为1/8，不能按温度端点推断为0/9。退化/非有限配置与无效输入由通用接口拒绝。

本轮复用328原厂算法和329因子，无新包获取、EEPROM读取或手机操作。Unicorn ARM64仅执行上述小函数、配置与距离/分类算术；memcpy仅拷贝仿真内存中至多128字节、sqrt数学stub处理异常平方根、日志stub，系统调用/异常拒绝，无Android加载器或原厂native运行。可重跑[check-inverse.py](check-inverse.py)。

五来源19个真实refPt根分别用factory与unit因子，共38个参考模型；每架构760个校准参考值及10450组节点/区间/离轨/随机输入，主机与AArch64均以Werror构建，色温、距离、光源分类与完整原厂包装调用结果完全一致，最大误差0。[结果](inverse-validation.json)。初轮仅端点光源标签不同，已按原厂常量修正后全过；不能将该初轮失败称色温计算失败或隐去最终范围。
