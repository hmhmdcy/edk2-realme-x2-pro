## 本机采样与源码差异

原HAL `0x362588…0x3626dc` 证实：前64个等效12bit节点先加1再除4095，**只裁剪node63**，node64保留初始化常量1；这与TMC10的归一化方式不同，不能直接共用。mix依据kneeY[1]／kneeX[1]计算，未直接套TMC10的darkGain字段。

实际执行 `0x3c7070` 的65点PCHIP和 `0x3c7c98` 的对比度处理。后者始终访问直方图曲线，并将最终Q10增益裁剪到0～8191；固定辅助源码有条件跳过曲线读取，且计算了上限却未应用。另一个边界差异是PCHIP的下界比较使用小于等于unity；在线性暗部增益低于unity、输出恰为unity时，不能改成严格小于，也不能用上下界倒置的std::clamp。

[采样检查](sampling-validation.json)有1192项：198个原厂区域的锚点乘3种增益、2种暗部比例构造1188份夹具，另4项有限但线性增益低于unity的边界；附加16项非法输入。**夹具的系数由固定源码膝点辅助函数产生，尚未执行本机完整TMC11膝点生成；直方图对比度曲线为合成输入，并非恢复的现场统计输出。**

对照归一化、mix、线性增益和最终Q10增益，主机ASan／UBSan与AArch64 SDK／QEMU各961568字节零差，输入保持、失败输出保持，`-ffp-contract=fast`通过。累计13171655条目标指令、77480次powf provider；powf使用主机libm，没有声称执行原Bionic。

固定源码PCHIP在1188份原厂锚点夹具零差，但4项补充边界相差7字节；固定源码对比度结果共16692字节不同。[源码差异](source-helper-r1-validation.json)作为不匹配证据保留，公共实现以本机指令为准。归一化轴与直方图曲线为显式调用方数据，未把原厂表嵌入公共库。

[采样首轮失败](sampling-r1-validation.json)也保留：两个架构各526字节差异只在一项非法输入夹具，测试误改kneeY[0]却期待拒绝kneeY[1]负值；字段实际偏移由280改为284后通过。原参考／两架构输出私存保留，未通过修改目标指令处理失败。
