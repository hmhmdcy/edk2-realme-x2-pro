## 原厂布局与内核改动

优先复用已保存的 CamxChi 固定版本、本机 HAL 和 ICP 固件，没有重新下载固件或访问 NV／OTP／persist。[来源与处理域](primary-sources.json)。本机 PD10 是 Camx format 18／固件 format 10、单平面。完整执行本机 `InitializeFormatParams` 和 `SetConfigIOData` 后，确认每个 2×2 块占八字节，行步长按192字节、打包行数按4对齐。较新参考源码另加的256字节／32行规则与本机结果不同，未照搬。

四分之一图像宽高为 `((full + 7) / 4) & ~1`；stride为 `ceil(width * 4 / 192) * 192`，slice为 `ceil(height / 8) * 4`。例如640×480输入对应160×120 PD10，stride768、slice60、46080字节；650×480对应164×120、相同backing大小。这里只确定内存布局，未推断实际像素位序或把 NV12 当作 PD10。

[补丁](coarse-io-layout.patch)修改三个内核文件。`camss_a5_ipe_pd10_quarter()`检查全尺寸输入与溢出边界，返回明确布局；共享 `camss_a5_ipe_encode_io()`可描述端口1的PD10粗级输入。所有校验先于写入，拒绝不匹配的尺寸、步长、slice或容量。普通配置仍传NULL粗级输入，原有NV12/NV21字节保持不变。没有新增用户API、板级配置或传感器改动；提交路径仍未引用这个可选粗级配置。

[实际C函数验证](io-validation.json)覆盖64组尺寸、端口8/9、NV12/NV21和padding，在宿主ASAN/UBSAN及ARM64静态qemu执行，156928字节完全一致。PD10布局与84字节端口描述符逐项对照真实原厂函数；其余NV12字段对照既有编码器。24个无效输入／容量／布局用例在每种架构保持输出不变。该布局检查包括小尺寸，不代表低于LTM最小粗级尺寸时可启用DC。

维护分支`samurai-ipe-coarse-io425`、提交`faf093770826a3bbe4b6f21f3b93303c62591627`。[源码复现](source-validation.json)确认零fuzz／零offset应用、维护树干净及实际源码哈希一致。[内核构建](intree-build-validation.json)以W=1、Werror完成24.27s，零诊断，两项变化对象实际重新编译；仅构建core，不声称重建其它helper模块。候选core SHA256 `ae2ca7e3ede81ccb019422d7250376c23377537d2c328571817a3390db179099`。共享构建输出已恢复到构建前状态；原来不存在的ICP产物也恢复为不存在。

## DC 开关的实际效果

[完整原厂执行](multipass-validation.json)直接读取上述ARM64 C输出的1216字节IO，使用424已生成的主摄实际LTM／色彩／Gamma程序。每组运行完整HAL Create/Execute/Destroy和ICP CONFIG_IO／frame prepare，未以provider替换数学或striping。宿主只提供既有内存操作／分配与固件框架接口；没有执行硬件enqueue或像素DMA。

两种宽度DC开启时，striping、32字节job、实际硬件命令及LTM控制均改变。将PD10 IOVA改址，完整固件输出只有对应输入地址改变，job相同，证实这个地址确实被消费；不是在命令中偶然找到一个常量。所需scratch为71488／75584字节，不能延用单遍48字节。CONFIG_IO内部+2896字段是配置遍次，不能误当成BL容量；HAL返回的最小BL容量另为181024字节。

424的单遍反例仍有效：没有粗级端口时，仅切换DC标志不改变命令。425证明的是补齐粗级端口后原厂程序怎样调度；尚未证明现场PD10生产、DC统计写入与全尺寸IP消费。scratch的额外空间未擅自命名为DC统计表，LTM控制差值也未据猜测拆成硬件位。

开发检查最初错误地要求DC关闭仍读取PD10并执行两遍；原厂执行否定了这一假设。已改为检查开关的实际差异，保留真实结果。源码检查也纠正“共享构建目录原先一定有core.ko”的假设，改为核对构建前后的存在性和内容；没有因此重建或改变设备。

## 生产路径和下一步

较新Camx参考的`UpdateFromDownscaleFlag`可指定IPE内部降采样，但本机`SetConfigIOData`路径没有该绑定，保留HAL也无对应字符串。**这些静态差异不足以证明本机全部内部降采样能力不存在**，因此没有添加未经验证的标志或提交空PD10缓冲。

固定参考的IFE DS4路径明确输出PD10，并启用`videoDS4R2PDEnable`；DS410、precrop、round/clamp与输出布局可继续用于定位本机实现。本机维护VFE175路径当前只注册FULL、params、stats三个输出，尚无DS4注册和DMA生命周期。优先恢复VFE175 DS4硬件生产，核对与FULL的尺寸／裁剪及SOF配对，再接IPE粗级缓冲、完整C striping和scratch分配。若继续查内部IPE生产，必须先用本机实际指令及地址写入证明，不能套用新版本行为。

完成生产与绑定后，才做粗级内容／统计／full-pass消费的实际验证，再与IPA同SOF触发和最终成功数学历史提交合并。GTM仍属于IFE/BPS处理域，本轮没有应用；原厂TMC非零GTM份额、上游未来IFE生效版本与对应图像IPE的因果绑定仍须完成。
