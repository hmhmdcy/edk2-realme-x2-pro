# 326：其余三摄个体数据读取与独立解码

2026-10-20。主摄GW1、前摄IMX471、长焦S5K3M5的个体EEPROM均已只读取得，WB和主LSC表完成解码/交叉核对。加上299/320已有的广角数据，四摄个体LSC主表现在均已保存并可解码。默认调校、软件包及内核保持325部署；本轮没有应用这三摄个体值，完整目标active。

先比较缓存与本机原厂清单：两份GW1描述相同可复用，前摄和长焦版本不同，因此仅从vendor以ro/noload/noexec补取当前两文件并卸载。按其类型表确认读取地址/长度，不能把旧完整EEPROM XML当作正确结构。[当前来源](descriptor-source-validation.json)、[只读计划](read-plan-validation.json)。

正常系统`cam --capture=0`提供硬件相机流并持有供电；第一次完成帧后开始I2C读取，读取结束即向拥有的cam子进程发SIGINT。没有构建专用持电程序，没有图像文件输出或新的帧数门槛。I2C每次只发送2字节地址指针，随后READ，未发送EEPROM数据写入。各新设备两次完整读回相同，传回主机亦核对；相机流共380帧只是读取期间的实际观察数量，不是画质测试。[读取](read-r2-validation.json)、[传输](transfer-validation.json)。

R1因内核没有可选的`/proc/PID/task/PID/children`接口，在开始EEPROM传输前停止，三次媒体/供电恢复均成功。脚本改为标准stat的PPid定位自身子进程，并用pidfd发送停止信号；不要求添加内核配置，也不把正常SIGINT交给fixture误判成子程序失败。R2三摄读回及恢复通过。[保留失败](read-r1-validation.json)。

沿用320从本机HAL确认的“51个packed40点后跳1字节”，主/长焦起点208，前摄512；每表17×13、R/GR/GB/B共884值，三份主表均无零节点，WB分母为正。GW1旧连续步长会产生3个假零，本轮没有修补任何读回字节。主摄两份命名描述的物理读取/WB/LSC映射相同，不能因此确定哪份golden或工厂调校适合本机。[解码](unit-decode-validation.json)。

长焦Illuminant2的GR低字节地址在原厂描述里写208，常规packed40位置应为209；其余四光源指向同一主表。解码器忠实保留该别名，所以长焦实际产生两个描述映射/解码表，不能把五项都当同一表，更没有替它自动改成209。后续可回退配置需明确选择光源索引，例如无该异常的0；完整运行时选择仍须结合golden/CCT核对。

独立C采用顺序游标，Python采用随机地址表达。主机及AArch64 Werror构建/执行，对三个实际设备、四种地址映射（包括长焦异常）和两份原始读回分别比较，每架构7072个通道值均一致。此项证明实现与帧布局对应，不能代替工厂有效性/checksum。[独立结果](decoder-crosscheck-validation.json)。原始字节、个体值、序列号及其指纹只在私有目录，未进入仓库或调校包。

另继续查本机HAL的AE同步路径：旧命名GW1分支在0x50323c指定主参考0x3400，调用0x505f18读取/保存36字节；这超出当前普通9984字节段，因此另以正常cam供电做36字节小范围只读，双读一致且恢复成功。该位置首字节为原厂拒绝哨兵，未检出可用主参考，不能把旧分支偏移当成本机有效标定。广角既有0x2d00记录、长焦本轮同偏移记录的数字字段为正；长焦字段解释目前仅共同36字节布局候选。未写persist或执行HAL。[偏移指令](ae-read-plan.json)、[小读](read-ae1-validation.json)、[语义结果](ae-reference-validation.json)。曝光参考的物理单位和主参考正确来源仍需核对，未应用同步系数或声称硬件帧同步完成。
