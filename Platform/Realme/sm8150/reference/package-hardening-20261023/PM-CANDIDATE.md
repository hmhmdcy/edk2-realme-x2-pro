# r1 为封存候选，暂不推荐部署

第二轮实测确认安装脚本仅为advisory，返回失败仍可能提交文件/数据库。必须采用外部事务入口，不能直接以旧hook作为安装闸门；详见STAGED-ROLLBACK.md。已签名r1不修改。

`0.1.0-r1` 只把 k363 的 hci_uart 换为 transport r1。它要求设备/release正确，现有三个文件仍为r0锁内字节，`bluetoothd` 已停止且 hci_uart 已卸载；钩子仅核对条件，不停止服务、卸载模块、执行depmod或重启。

本轮补丁纠正 SLEEP 单字节写入必须返回1，零/非预期非负返回变为EIO，并传播负的等待返回。33例实际函数模型中旧实现16违例，候选0；构建和符号证据随包保存。185功率脉冲与H4源码不变。

transport随后发现原有失败恢复路径会删除唤醒timer但仍保留TX_WAKING，而resume只清suspend标志。r1没有补齐该恢复边界，不能据构建/模型通过推荐部署，主线正在等待r2。此包独立封存；尚未安装或实机验证，不代表蓝牙PM、配对、连接或音频通过。
