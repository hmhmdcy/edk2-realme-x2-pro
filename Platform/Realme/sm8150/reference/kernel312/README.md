# 312：六模式选择、默认3A和图像缓冲恢复

2026-10-19。已通过标准sensorConfig选择当前板级暴露的六种传感器模式，并接入按实际模式时序匹配的调校目录。应用仅选择传感器尺寸，直接camera.start()即可启动AE/AWB，无需逐摄像头指定profile或启动曝光／WB参数。两种新增模式的控制延迟已独立测量；同时修复缺图像缓冲导致自动算法挂起及控制元数据缺失的问题。完整个体校准和产品硬件接入仍未完成。

## 现有实现的复用与分层

参考SDK内RPi pipeline的sensorConfig校验和现有CameraSensor接口，使用标准bitDepth／outputSize选择实际传感器格式；不新增应用专用选模接口。[CameraConfiguration文档](https://docs.libcamera.org/master/public-api/classlibcamera_1_1CameraConfiguration.html)。当前后端支持Bayer10，任意模拟裁剪／binning字段尚未实现；不能据此称完整SensorConfiguration模型已支持。

复用IPAProxy::configurationFile及标准LIBCAMERA_IPA_CONFIG_PATH查找camss-vfe/<model>.yaml。版本2目录按width、height、pixel_rate、line_length和最小frame_length精确匹配，重复匹配或未知时序拒绝；保留版本1兼容。不会把一种模式的控制延迟套到另一种模式。

带AGC／AWB的模式配置将对应ControlInfo默认值设为自动，IPA和pipeline使用相同默认值；应用显式请求仍优先。库、IPA和代理必须匹配使用。本轮只改通用用户空间及模组模式配置，内核、DT、板级供电、传感器源码与系统包保持。[补丁](mode-default-recovery.patch)、[源码状态](source-state.json)、[构建](build-validation.json)。

## 缓冲恢复与已保留失败

r1首次默认目录解析在0帧失败：共享数据被PyYAML生成为锚点／别名，libcamera不支持；改为普通YAML后修复。r2前摄1928达到了AE目标，但自然缺一个图像缓冲使旧映射检查把整个ISP参数队列永久标为不健康，AWB停在两次更新；该结果保持失败。改为更新请求／SOF映射后，r3自然缺帧恢复并收敛。

主动暂停归还四个图像缓冲120ms进一步暴露两项问题：旧的固定四帧统计龄限制使AE永久失效；没有统计包的有效图像缺少控制元数据。现在比较统计帧与当前的实际曝光／增益／source上下文，一致时接受滞后提议；缺统计时只从对应SOF已确认参数和传感器历史恢复控制元数据，AwbLocked设为false，不伪造直方图或锁定状态。未知上下文仍不能伪装成有效控制。

r4、r5的失败原样保留。r6实现恢复后完成32帧，但250ms等待造成77个未输出帧槽、6帧需恢复元数据。最后根据已按序到达的较新统计及在途缓冲判断旧包已缺失，在参数确认后尽早完成对应图像；保留超时用于尚不能判定的情况。

r7同样120ms暂停后完成33帧，末端AE/AWB重新稳定，未输出帧槽降为13，2帧无统计图像的控制元数据均与历史一致。没有声称暂停期间无损或零延迟；严重SOF事件丢失、超出历史窗口、重叠手动控制及更长积压仍待覆盖。[最终恢复](default-r7-validation.json)、[此前恢复停顿](default-r6-validation.json)。
