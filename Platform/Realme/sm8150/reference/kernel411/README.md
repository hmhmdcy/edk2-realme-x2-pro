# 411：按本机 HAL 修正 TMC10 膝点，补齐 AEC 插值

本机原厂指令对照发现，410固定参考源码的近 unity 阈值和增益索引精度与本机版本不同；已修正[共享 TMC10 实现](../kernel410/libipa/tmc10.cpp)。原有1301项中100项膝点／百分比结果、70项采样及58份最终 LUT 受影响，最终表共4044字节变化。新增[AEC 区域选择与插值](libipa/tmc10_aec.cpp)，完整原 HAL 函数、主机和 AArch64 对照通过。**实际运行时 TMC10／11选择、TMC11 的DRC／HDR树及产品与实机接入仍待完成，完整目标保持 active。**

## 本机版本差异与膝点检查

继续优先复用固定[仓库来源](primary-sources.json)、410已与原厂XML核对的5个供应商根／18区，以及本机原 HAL。源码只作为定位参考，本机原指令未修改。原厂文件、数据、参考程序和反汇编仍全部私存。

定位到完整 TMC10 插值与膝点函数入口 `0x3774b0`，其中 `0x377a08…0x377d50` 在区域插值后计算膝点、系数与百分比。目标使用 `logf` 与 float 商后取整，410源码对照使用 double 商；目标只保留精细的 unity 比较，没有公开源码额外的0.0001近 unity 扩张。当前共享实现按本机行为收敛。[旧实现与目标的失败对照](prior-source-r1-validation.json)保留，不能把410修正前“源码一致”当作当前本机一致。

[膝点／采样检查](knee-validation.json)共2643项：原1301项，加95个半索引边界各7个相邻float点、分别驱动普通与暗部增益，共1330项，以及12项近 unity 边界；另有33项非法输入。膝点、6系数、百分比、mix、65点增益及原子拒绝输出，在主机 ASan／UBSan 和 AArch64 SDK／QEMU 各909840字节零差，启用 `-ffp-contract=fast`。2640项膝点有限、2598项采样成功；零归一化端点及非有限结果仍按明确的接口契约拒绝。

该检查实际执行3371838条目标指令；7929次 logf、176886次 powf 由主机 libm 提供，未声称执行原 Bionic 数学库。增益采样仍是目标 `0x3c6328` 的65点／Q10特化；mix仍对照 `0x3626f8…0x36273c`。

## 完整 TMC10 AEC 插值

[新接口](libipa/tmc10_aec.h)保留全部11个区域字段及原顺序：在当前区域内直接取值，只在与下一区域的间隙中插值，支持 lux index 与 real gain 两种控制。插值比例用 double 差值再舍入为 float；字段插值沿用整数／小数分开计算、放大1000000再分别舍入的规则，不能改成普通 float lerp 或融合表达式。

原厂五份根都选择 lux 控制；其未使用的 real gain 轴包含相互重叠的默认范围。接口按目标的“首个匹配区域”语义处理重叠，不排序或重写原厂数据。测试中强制切换 real gain 仅为数值夹具，不代表改动原厂配置。整数转换无法表示的插值输入被拒绝，避免沿用未定义的转换；失败保持输出，输入区域保持。

[完整函数检查](aec-validation.json)含687项原厂边界／区间／过渡扫点及150棵合成树，共837项、另11项非法输入。比较了选区索引、比例、全部11字段，并继续到膝点／百分比／mix和采样增益。主机与 AArch64 各339200字节零差；完整目标函数和采样累计1329895条指令。237项使用原本关闭的根，仅做离线数值检查，没有启用这些根。**这只补齐 TMC10 的 AEC 层，不等于 TMC11 的DRC／HDR／AEC多层树。**

初始[膝点布局夹具失败](model-r1-validation.json)误将目标输出+16的kneeX与+32的kneeY读反；修正读取顺序，原指令不变。[AEC首轮失败](aec-r1-validation.json)两个架构各108196字节差异，根因是夹具将输入+16的realGain与+20的luxIndex写反；修正实际ABI后通过，公共插值数学未因该次差异修改。失败参考及两架构输出私存保留。最初脚本曾与Python标准库inspect同名，已重命名为inspect-tmc；未涉及目标代码。
