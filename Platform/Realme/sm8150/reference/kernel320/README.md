# 320：修正本机原厂LSC数据分组，四个零节点已消失

2026-10-20。离线反汇编本机原厂HAL后，找到与公开通用CamX不同的LSC读取规则：每51个packed40点额外跳过1字节。此前304／317按固定5字节步长连续读取，跨组后逐渐错位；4个零节点来自错误解码，没有修改或补造EEPROM值。

真实地址公式为`208 + 5 * point + floor(point / 51)`，221点共1109字节。四个跳过字节在保留样本中均为0xff；本机格式循环不消费它们，不能把它们擅自当作checksum。原始读回、NV和个体校准未写入，手机保持318已部署基线，LSC默认关闭。

原厂HAL SHA仍为`e2b1b9b6379507052464d9f9573c2a5a1b1cf37c43947b53645ddc8948a70dde`。通过FormatLSCData字符串引用和FDE定位到内联格式函数；原始字节与反汇编私有保存。[定位工具](locate-stock-lsc.py)。关键代码位置：

| 位置 | 已确认行为 |
| --- | --- |
| 0x4fe070～0x4fe130 | 按高低位mask提取四通道，形成R/GR/GB/B浮点表 |
| 0x4fe00c～0x4fe06c | 普通点增加模组描述的r/gr/gb/bIncrement |
| 0x4fe134～0x4fe154 | 用乘法／移位计算点计数对51取余 |
| 0x4fe158～0x4fe1a4 | 每51点使四通道高低位地址额外增加1 |

[Python直接解码](decode-stock-lsc.py)与[C顺序分组解码](decode-stock-lsc.c)分别实现随机地址和顺序游标；主机／AArch64 Werror构建、跨组非对称向量通过，两份原始读回的884个通道值全部一致。[结果](stock-lsc-layout-validation.json)。

修正后884个值全部非零。归一化相邻差分能量由旧候选的0.68～0.95降为0.0525～0.0536，与原厂golden表约0.051～0.054相近；这是布局正确的辅助证据，不能代替原厂有效性／checksum或画质检查。单纯在读回里滑动packed40窗口没有找到同样平滑的候选，未采用启发式结果改变偏移。

七个原厂LSC根实际有两种不同golden、17种不同基础表，因此仍需确认模式／触发选择，不能把所有根视为同一调校。纠正后的golden/unit候选因子已计算，全部非零正值，实际数值保持私有，未部署。

还需确认模组／golden绑定、有效性及checksum，并将319重采样接入IPA。IMX319原厂222MHz模式还存在真实模拟窗口与binning后数字裁剪的区别，不能用模拟窗口宽度直接除以输出宽度猜测采样步长。正式颜色／阴影／几何校准仍未完成；用户关灯不影响这些源码和内部图案工作。
