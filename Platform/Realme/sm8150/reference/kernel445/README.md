2026-10-23。在 [444](../kernel444/README.md)基础上，新增 [0057](0057-camss-exact-focus-grid.patch)预计算坐标、以滑动窗口复用九点和；取整、阈值、区域统计与最终 FoM 保持一致。宿主 ASAN／UBSAN、实际 ARM64 及四份旧实拍 FULL 均通过逐项对照，手机缓存样本基准约快 2.04—2.07 倍。720p／1080p 两路隔离消费者共 240 帧通过同 SOF／实际版本／成功历史审计。**焦点长尾和整体录像帧率仍未收敛，1080p 本轮帧率没有改善；候选未永久安装。**

手机恢复正式 440 r32／r27、434 三模块及四份原有私有配置，epoch 作业 0、taint 0、四设备 suspended，P/W 各一个 uid10000。[恢复检查](current-state-validation.json)。未刷写、触发重启或写 EEPROM／NV；相机测试与充电只读窗口按约定串行。

## 源码与精确性

已有核心使用 `-Os`。原有网格内层重复进行坐标与区域除法，平滑阶段逐像素重复九点累加；新版本只预计算最多 320 个 x 坐标和区域索引，将 y 坐标／区域行移到外层，并在平滑窗口右移时减旧三点、加新三点。每次仍对完整九点和做一次 `/9`，没有提前取整或改变采样位置。九点和最大 `9*65535`，更新时减数属于当前窗口，不引入溢出或下溢。

只改私有 `hardware_focus.h` 和管线计时两个生产文件，原 `FocusStatistics::figureOfMerit`、AF 状态机、IPA6、原厂调校与 441 build4 模块不变；补丁零 fuzz／offset 重放。[源码验证](source-validation.json)。没有跳过 FoM、降低网格密度或更换 AF 判断标准。

[实际函数对照](focus-validation.json)从旧／新生产头提取原函数体，检查 valid、12 个区域各自的 energy／sum／samples 和最终可选 FoM。两架构各覆盖 54 个有效输入、62 个非法边界，包含最小／奇数尺寸、填充 stride、黑／白、阈值附近、坡度、噪声和棋盘。ASAN 使用最小合法 backing，非法尺寸／截断／空指针保持拒绝。另复用 442 r9 四份真实、IPE 前的 FULL，逐项相同，FoM 也与当时实际 AF 日志一致；未重新拍摄这些基准样本。

核心增量构建 117.76 秒成功，SHA `15844147…`。IPA `4c90047d…`、签名和代理 `c7887708…` 与 444 逐字节相同，复用其真实 IPA6 与签名契约；private profile 仍为 443 的原厂 mode4 绑定。[构建](build-validation.json)、[载荷核对](runtime-inputs-validation.json)、[重入边界](reentry-validation.json)。

## 手机基准与实际取流

手机使用四份已有 FULL，在同一进程／同一输入上交替执行新旧函数各 16 次。旧中位 2.060—2.547 ms，新中位 0.999—1.250 ms，比例 2.038—2.071；区域／FoM 保持相同。这是缓存 CPU 样本，不包括实际 DMA／映射，不能单独证明整个相机提速。

## 分段证据与续作

新增计时分别记录 DMA START、映射、采样／统计、FoM 评分、解除映射、DMA END；保留原同步和所有权顺序。两路全部 240 个入队帧均由采样／统计阶段占主要耗时：其中位约 4.18／4.26 ms，最大约 69.6／70.2 ms；映射中位约 0.08／0.15 ms，评分约 0.004／0.006 ms。计时的“采样”包含两块临时网格的分配、读内存、滤波、区域累加、可能的页故障与调度，不能直接称为纯算法 CPU 时间。

已有内核实际使用 vb2-dma-sg；本轮只读核对了其 `alloc_pages`／`vm_map_pages` 和标准 CPU／device 同步路径，没有切换内存属性或绕过 DMA 同步。仍需区分采样阶段的分配／访存／调度长尾，可评估有界工作区复用并继续要求统计／FoM 精确等价。同时继续协议6候选的其它模组、RAW／双流和实际 AF 覆盖，再决定发布；不能让主摄性能微调替代完整多摄、光学校准、录像／HDR、第五2MP与几何／同步目标。
