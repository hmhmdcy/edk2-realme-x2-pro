相同 UID 只是各文件内的编号，不表示套用了相同的调校表。[配置导出](export-rear-profiles.py)分别读取 350 的后级 Gamma、351 的 LTM／IPE CCM、412 的 TMC、426 的 DS4 和 432 的 GTM 原件；模式选择沿用 343／431 与原 GetModule 已交叉验证的普通 Preview 上下文。DS4 明确取所选 full_dc4 模块 PASS_FULL 的三项系数，没有改用 DS16／显示路径。

长焦原 TMC10 关闭，TMC11 却开启；本轮保留差异，不以旧版关闭推断没有 ADRC。各自 rear IPE CCM 全树为单位矩阵，保留已有 IFE CCM；所用 CST／CV 桥和 TMC 通用轴是原已验证的公共处理域参数，各摄像头的 LTM／TMC／Gamma 调校独立。

当前输入政策仍是单曝光、线性 AE、无 face，父坐标明确为 DRC1、HDR 比值1、LED0。广角 Gamma 原树含多个 HDR 节点；导出按其原控制轴在比值1选定合法分支，没有把其它 HDR 分支的支持算完成。所选分支的 Gamma CCT 节点仍要求唯一，因此没有擅自丢掉动态 CCT 插值。[配置核对](rear-profile-validation.json)。

对实际编译的 ARM64 profile 对象，分别执行配置、三组 GTM／TMC 状态、原生 histogram hold／触发刷新和匹配上游 TMC 的 LTM 计算。[数学检查](rear-math-validation.json)。6 份实际输出的 GTM LUT 又交给各自原厂解析对象和完整 HAL 计算，512 字节各零差异：[原厂完整计算对照](native-gtm-validation.json)。没有重新下载固件或重读 NV／OTP／EEPROM。

## 黑电平与配置边界

当前正式 420 私有配置的主摄、广角、长焦及前摄普通全幅模式仍有零 BLS 实验值；436 已先修正主摄候选，本轮在各自候选中修正广角和长焦。正式磁盘文件没有被临时试验替换。

独立有界解码复核广角 16 个 IFE 根／288 区域、长焦 19／152，分别与 299、306 原厂解析器记录的同一源指纹及数值对应；IFE 各区都为 960 U14、四阈值0，并非误取长焦 BPS 的990。本轮另用原解析器核对前摄唯一 IFE 根／5 区域，结果相同，供后续前摄接入使用。[BLS 证据](bls-validation.json)。后摄各自恢复 U16 减量3840及显式范围归一化2175／2048，不宣称个体暗场标定完成。

## 实机与适用范围

两路为普通原生 IPA。每帧均核对统计来源早于实际 GTM 生效图像、真实 cookie／generation、同 SOF PD10、IPE 入队和最终成功历史，上一 lux 来自上一成功提交；各自观测两个 GTM bank。每颗最后一次已排队但未观测回执的提案不算生效。广角有2个、长焦有3个启动帧，未硬套主摄的延迟帧数。

AWB 连续8锁定中，广角4帧、长焦5帧没有重新计算，但都保持相同实际 WB 增益，符合437状态修复。末端 CCT 4864／5934K只是各自视野下的参考模型估计，不是多摄白点一致性标定。图像可辨识，仍可见室内噪声及场景／光学差异，没有色板或均匀场的绝对验收。
