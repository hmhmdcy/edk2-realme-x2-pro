# 319：用户空间LSC网格重采样

2026-10-20。新增可移入libipa的模式网格选择和重采样函数，主机及AArch64构建／测试通过。本轮没有操作手机或改变已部署包；设备保持318已验证的CAMSS＋r25/config-r20，LSC默认关闭。完整目标active。

[接口](libipa/lsc_resample.h)明确要求源标定网格跨度、输入首个Bayer quad的源坐标及相邻quad的坐标步长。负步长表示镜像。输出分辨率不能独立确定裁剪、binning和采样中心，调用方仍须从真实模式确认映射，不能把尺寸相同当成校准位置相同。

网格选择依据318已验证的寄存器范围和[固定版本LSC34源](../kernel317/lsc-primary-sources.json)，在17×13覆盖约束下选择插值细分与居中起点。重采样用内部点Catmull-Rom双三次、外边界双线性，一格边界延伸保持边缘斜率，最后限幅到1～8191/1024。角点沿对角斜率延伸；不凭空向远离标定区域的位置外推。调校和重采样均在用户空间，不给驱动或板级DT添加模组数据。

主机Werror测试覆盖网格恒等、仿射裁剪／binning、双轴翻转、六种尺寸及无效输入保持输出；同一测试在现有Alpine AArch64 SDK里编译并经QEMU执行通过。[构建](resample-build-validation.json)。最初尝试独立aarch64-linux-gnu-g++发现工具未安装，已复用现有SDK，没有另装工具链。

全部75个原厂基础表在六组尺寸／仿射映射下重采样，与独立Python Hermite基函数表达对照；450份结果的397,800个float和198,900个DMI编码字全部一致。[交叉结果](factory-resample-validation.json)。这些映射用于数学验证，不声称就是本机六个传感器模式的真实光学坐标，也未应用原厂个体值。

[实现](libipa/lsc_resample.cpp)复用317的网格类型，校准合成和Q10编码仍由317处理；尚未挂入产品IPA或发布新包。下一步确认传感器模式的实际裁剪／采样中心和标定方向，增加IPA参数适配及调校配置选择；原厂个体表4个零节点、模组／golden绑定及有效性／checksum仍待解决。318已证明硬件网格可工作，不等于完成真实模组阴影校准。
