# 345：原厂曝光分配与帧时长 knee 数学

2026-10-20。已独立实现原厂曝光表查找及帧时长 knee 推导，新增通用 `libipa/aec_exposure_table.{h,cpp}`。主机与 AArch64 分别对照保留原厂函数通过。本轮只新增通用数学与离线工具，没有接入 IPA，也没有改 344 已部署的默认私有配置、软件包、板级 DT、驱动或内核。完整适配目标仍 active。

来源是 328 留存并已与本机 vendor 对应的 `com.qti.stats.aec.so`，符号沿用 336 从其 `.gnu_debugdata` 恢复的结果。完整 `CExpTable::ExpTableEntryLookUp` 指令区间为 `0x2d9a0..0x2dbd8`；`UpdateFPSKnee` 为 `0x2d178..0x2d350`，内部仍调用前者。没有另找不相干平台的 AE 公式或重新下载原厂载荷。

表查找按原厂 float32 比较和边界选择，夹到首末 index，并在相等节点选择最后一个已达到的 knee。使用单精度 `powf(1.03f, Δindex)`；Gain 优先先提高增益到下一 knee 的比值，再提高时间，Time 优先反之。原厂把声明的 Maximum 枚举值也走 Time 分支，该数值行为保留。实际 224 表只有 Gain/Time 两类。

曝光时间不是整体浮点相乘后转换：保留精确 uint64 基值，只截断 `(timeRatio - 1) × float(baseNs)` 的增量，再做整数加法。保留原指令对负增量返回 0 的行为；非法输入及无法表示的整数加法溢出由通用接口拒绝，不执行可能回绕的结果。请求负零的比较边界也与原厂一致，不用 `std::clamp` 隐藏其符号差异。

帧时长 knee 先按原厂时间比较找到基段；Gain 优先时将下一段增益比转换成 index 偏移，再加入时长比偏移，最后调用同一原始表查找。沿用 336 恢复的精确双精度常量 `77.898529052734375`，不重新计算 `1/log10(1.03)`。结果 knee 的优先级设为 Gain。该函数还不是硬件限时器；实际调用者仍需应用传感器行/帧预算。

- 224 张保留原厂表包含 42 种不同 knee 程序，数值相同的程序只测试一次。表查找每架构 1,314 项、26,280 字节零差；267 项同时核对原始表和 active 表读取入口。覆盖所有实际 knee、相邻 float、区间内部、边界夹取，以及重复节点、负 index、整数基值和非法输入。[表查找结果](math-validation.json)。
- 完整 FPS knee 函数及嵌套查找每架构 905 项、21,720 字节零差，包含各原厂 knee 的相邻纳秒时长和常见帧时长、不同优先级；输入 0 时长由通用接口拒绝。[FPS 结果](fps-knee-validation.json)。
- 复用已通过输出分析数值边界，无重复仿真或采集。在不低于表首时间的案例中，原厂输出有 203 项超过输入时长，最大 48 ns；照原规则保留，后续以实际传感器量化与限幅收敛。[舍入观察](fps-rounding-observation.json)。

原函数通过已有 Unicorn AArch64 环境执行，不启动 Android 加载器或原厂算法服务。`powf` 由主机 libm 桩提供、`log10` 由主机数学桩提供，日志亦为桩；这些不是本机 Bionic 数学库逐指令执行。新 C++ 以默认浮点编译设置、C++17/O2/Wall/Wextra/Werror 在主机和 SDK AArch64 构建，未因本轮重编完整框架。两架构在这组输入上均与上述明确参考完全一致。

尚未完成 `UpdateEVKnee`、`ApplyActiveTableEVFPSKnees`、anti-banding、实际传感器预算和 IPA 自动曝光分配接入。不能把两个函数通过说成整个原厂 AE 已移植。343 的模式/用途和普通 Streaming 表 0 选择继续复用；实际安装时仍需选主摄 mode4 的 Arbitration190、前摄 Preview144/Video441，不能因为 anchor 相同就使用 Default 全表。
