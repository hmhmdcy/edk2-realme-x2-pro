# 337：Bayer统计到原厂lux亮度的普通RGB路径

2026-10-20。已恢复并实现原厂普通RGB Bayer统计的亮度计算、16×16汇总和lux衔接。主机/AArch64默认编译器FMA设置、Werror各1523组/29636字节与原厂指令参考逐字节一致。发现当前CAMSS32×24网格不满足原厂横纵16倍数约束，需要先调整SoC统计网格再做实机接入。本轮无设备操作，335已验证的候选IPA/334内核及现机安装状态不变，完整goal active。

本轮范围是当前CAMSS实际输出的普通RGB、无独立饱和和扩展数据路径，通道次序R/B/GR/GB，与公共Bayer结构和当前驱动一致。每个通道把`总像素数−有效计数`作为饱和缺失数，乘相应高阈值补入总和。绿色先对两个绿色总和求整数平均再转float；随后按原顺序执行R/G/B权重、8位缩放及明确的上游normalization。饱和比例也保留。颜色补偿启用且增益有效时，按当前增益×调校权重÷参考增益计算新权重，未额外归一化；非法参考/输入增益沿原逻辑回退基本权重。[通用实现](libipa/aec_bayer_luma.cpp)。

全部有效区域、采样步长1时，原厂按网格整数分组累加到16×16，并逐格除计数。普通处理先要求横纵均为16倍数，总区域最多3072。当前32×24的行数24不满足要求，不能通过简单取平均冒充原厂完整网格语义。已验证16×16、32×16、32×32和64×48；当前硬件ABI最大768区域，因此32×16是可保持现有容量、无需扩大数据结构的后续硬件适配方向。当前driver仍32×24，未宣称已更改。

颜色权重补偿后，8位缩放亮度可能超过255，原厂普通lux包装没有在此截断。336通用平均函数原先人为拒绝大于255输入；337保留其其它已验证数学，去掉这个上限，并加入实际超过800的补偿亮度案例。原336历史源/证据保留；后续集成应使用本目录的`aec_lux.{h,cpp}`与`aec_bayer_luma.{h,cpp}`，不要只复制336旧平均函数。
