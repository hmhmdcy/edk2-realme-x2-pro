# 404：原生 LTM 全帧条带几何与原厂硬件命令对齐

补齐处理裁剪、网格、DC状态和完整条带编码，并让旁路／LTM共用底层实现。最终126次对照覆盖尺寸边界、NV12／NV21、单／双核、行距／切片填充，以及独立IQ字段和DC／IP／mask组合；生成的整512KiB CDM与32字节job均与完整原厂HAL／固件一致。**这是全帧1:1几何编码，尚未接入LTM运行时，也未完成LTM数值调校或实机像素验收。最后设备证据仍为402。**

## 修正与实现

复用本机原厂HAL／固件、403保存的30个原始几何对照，以及既有目标指令模型，没有重新下载固件或读取个体校准分区。扩展模型仅配置明确的IQ和布局输入；完整原HAL条带与原固件CONFIG_IO／帧准备执行到硬件enqueue前，未替代条带数学。

处理区域与输出区域需要分开：mask滤波的内部处理边界向左右扩展2像素，更新处理长度、裁剪与LTM网格起点；输出端口、后续裁剪、平面长度及径向坐标保持原输出范围。fetch／工作量则按实际读取范围计算。首个原型将所有裁剪和径向坐标一并扩展，640×480仍差19字节；分开后四个初始配置完整命令零差。

数据收集状态也不能直接用288×216硬阈值。沿原HAL实际写入／复制路径追踪，完整原分配函数先计算 `((dimension + 7) / 4) & ~1`，检查四分之一尺寸至少72×54，再将IP状态传给全帧DC。偶数全帧临界点为282×210。初版在286×214、288×214和286×216的单／双核各差1字节，[初版失败记录](serializer-r1-validation.json)保留；原厂输出及有界写追踪私存。

独立IQ检查还发现：**只有IP与mask filter同时开启，才选择324步长／6像素halo及扩展处理边界；否则使用328／4。** 403仅在mask开启夹具下得到324／6，不能外推为任意IP配置。新增类型化`mask_filter`字段，DC状态仍依据原始IP开关。650宽双核、IP开启但mask关闭时应是两条，不能沿用mask开启的四条。[遗漏mask条件的失败记录](iq-geometry-r1-validation.json)保留，最终覆盖全部八种DC／IP／mask布尔组合。

[内核补丁](ltm-geometry.patch)增加`camss_a5_ipe_ltm_size`和`camss_a5_ipe_encode_ltm_striping`，统一内部`ipe_encode_striping`。旧旁路API传入全关闭几何标志，保留调用接口和输出行为。新接口只接收类型化几何标志，不接收任意CDM／寄存器数据；所有可能失败的检查在写输出及`used`前完成。输入／输出仍为相同尺寸、相同UV顺序、全帧1:1、128…8192偶数尺寸及合法偶数填充，端口8／9、核心1／2；缩放、旋转和多pass未在此实现。

## 验证

- [78个尺寸／格式配置](serializer-validation.json)：30个403保留原始对照，加尺寸上下界、282×210附近DC边界、条带数量边界和NV21开关组合。主机ASan／UBSan与AArch64 QEMU各输出373152字节一致；非法输入、短容量、输出参数及尾部保持通过。
- [16个填充布局配置](layouts-validation.json)：输入与输出采用不同stride／slice，包括650宽双核和326宽单核；完整命令／job与原厂一致，旧旁路包装器及紧凑／填充几何输出一致。
- [32个独立IQ／mask配置](iq-geometry-validation.json)：16个独立合法字段输入及16个显式布尔组合；覆盖mask关闭时条数减少、640／650／128／8192宽和单／双核。两种架构的实际候选C输出一致，完整命令／job零差。

以上126次完整CDM对照共66060288字节，另4032字节job。它们包含重复几何下的不同IQ／布局条件，不称为126种不同分辨率。LUT为全零的离线几何夹具，从未作为实际调校提交。原HAL未初始化或固件未消费的padding不要求逐字节复制；最终比较的是完整下游硬件命令和job。[模型源码核对](model-source-validation.json)确认测试函数与候选实现对应。

候选源码、分支和commit见[源码状态](source-state.json)；[W=1／Werror构建](intree-build-validation.json)及共享配置／输出恢复另行记录。候选未部署。板级DT、传感器、主线框架、用户空间、Gamma opcode1及请求DMA／复位生命周期均未新增改动。
