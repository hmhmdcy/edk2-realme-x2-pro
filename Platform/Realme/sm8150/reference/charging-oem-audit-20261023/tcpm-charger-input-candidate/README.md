# TCPM工作额度接入MP2650

2026-10-25，离线候选。手机真实10小时测试运行期间不安装、不重启、不切USB。

当前506的MP2650驱动取原生USB预算，508已实测的TCPM默认Rp回调也取该预算。本候选补上后半条链：原生USB → TCPM → MP2650。只有板级显式配置`typec-supply`固件引用时才读取TCPM；旧板级未配置时保留原来的预算读取路径。不存在原生USB反查TCPM或反查MP2650电压的循环。

读取TCPM的`CURRENT_NOW`工作额度；`CURRENT_MAX`仅作一致性上界，不能把PPS支持3A误作已协商3A。兼容PPS/AVS能力类型仍在固定供电模式的情况。完整额度连续读取两次，再在电芯采样后重新核对；错误、零额度、未知模式和不一致均停止授权，不回退到旧BC1.2结果。这是软件一致性检查，不是电气原子性证明。

物理在线仍由原生USB与MP2650 REG13共同确认。TCPM重新协商的ONLINE=0不清除充电周期、Full历史或故障锁。订阅TCPM供电通知时仅排队驱动工作，不在通知回调内取得MP2650互斥锁。可选供应者通过真实固件引用解析，使用现有路径的模块引用及托管device link生命周期规则。

原厂对照复用已有Realme Android R仓库固定提交`23172a1571bd91156032cc9fef16284a82b63d2c`的`oplus_battery_msm8150Q.c`：`smblib_set_prop_pd_active`关闭APSD，先采用保守初始额度，`smblib_set_prop_pd_current_max`仅在PD生效时更新额度。本候选只实现工作额度消费；APSD/QC与PD的控制权交接仍待整合。原厂输入文件继续私存，没有重新下载。

实际函数测试见[test-result.json](test-result.json)：38例覆盖额度/能力区别、两次快照与电芯采样期间变化、错误无回退、物理断开与重新协商区别及通知暂停。测试提取实际驱动函数，仅模拟其IO边界，使用ASan/UBSan和`-Werror`；所有未涉及的已有函数逐一比较相等。单模块构建结果另见`ko-result.json`，未部署即不代表实机协议验收。

现有恒流、电压、电芯、温度、Full、计时、REG14唯一读者及停止逻辑保持。此处TCPM的电压是协议额度，不是ADC实测。本候选不更改PDO，不发协商电压请求，不启用9V、PPS、QC或VOOC。部署仍需完整板级控制权整合和相应实机测试；当前运行的是506原模块。
