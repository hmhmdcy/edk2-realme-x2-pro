# 383：内核原生分区计算与原厂完整帧准备差分

将旁路条带的分区计算落入内核，并建立可核对整个原厂 CDM 输出的离线验证器。当前完成分区范围组件，**尚未生成完整固件 striping blob，也未消除运行时条带文件依赖**。整体目标 active。

## 已实现的 SoC 组件

新增 [camss_a5_ipe_bypass_partitions](bypass-partitions.c)，在模块关闭、全帧1:1的8位线性NV12/NV21路径中，按目标原算法的328像素分区策略确定数量，再对核心数1/2取整。内部边界对齐到色度，输出按从右到左排列，边界保留4像素fetch halo。

宽度范围128～8192；验证参数、容量后才写入，非法输入或空间不足时保留输出及count。与完整原HAL算法对照76组，包含328/330、656/658等临界邻域、不同高度、端口8/9及NV12/NV21；inclusive输出范围无空洞或重叠，fetch不越界，ASAN/UBSAN通过。[分区验证](partitions-validation.json)。

这不是将320写成固定stripe宽度。比如原算法328宽/单核仍为一条，330为两条，656为两条，658为三条；双核对应数量再取偶数。范围和数量均由参数计算。测试过程中也确认显示输出范围位于stripe+20，视频输出范围位于+24，避免将显示范围错当视频范围。

维护源分支 `samurai-a5-ipe-partitions383`，提交 `a9f823f210344ab551e4859b4889358916345fbb`，父382 `47475238dc6a0d4b28a5db22b0c1af223dc50297`。[内核补丁](bypass-partitions.patch)。真实k363配置 in-tree W=1/-Werror构建无诊断，测试模块与382字节相同，候选未安装。[构建](intree-build-validation.json)。

本轮只增加SoC内核算法组件和验证器，未改板级DT、媒体核心、传感器或已安装用户空间。分区函数尚未接入现有单帧提交函数，不能据此宣称原生完整IPE后端已经完成。

## 原厂固件消费路径与观察器修正

执行保留的原固件 `DoFirstRead`、完整CONFIG_IO、帧几何整理及CDM准备，停在 `HardwareDriver_EnqueueJob` 入口0x220a2，**没有执行硬件提交或像素DMA**。SoC标识寄存器使用模型值0x10705；OS分配器、日志、流句柄/私有上下文及命令回收为模型，几何和CDM算法未用桩替代。[准备差分](preparation-validation.json)。

覆盖640×480、1920×1080、4608×3456 ×输出8/9 ×核心1/2共12组。有限范围内存观察和无观察器执行生成的整个512KiB CDM缓冲与32字节任务描述符逐字节相同。固件读取的striping字节数分别为534、1330、3121/3320；这些是消费轨迹，不是完整字段定义或所有模块的读取上界。

完整原HAL算法另以0xa5和0x5a两个互补初值填充分配器与输出区，识别随旧存储变化的位；将这些位规范为0后，上述12组原厂固件生成的整个CDM缓冲及任务仍逐字节相同。两个脏初值本身的CDM输出也相同。该证据支持后续实现时消除填充垃圾，但只覆盖当前模块关闭夹具，不能扩展到启用IQ后的结构语义。

最初全局内存读钩子导致离线Thumb执行栈不平衡。最小复现中，同一个原始 `FreeCdmProgramArray` 空数组调用，无钩子或限定到无关地址区间时SP平衡；全局空回调却遗漏正常返回序列并产生-32字节SP差。已弃用全局观察，以限定striping范围观察并进行完整输出差分。[观察器证据](observer-validation.json)。这是当前Unicorn2.1.4环境中的观察结果，不能归因于手机固件故障。现有reference内更早模型未发现使用该全局读取钩子的脚本。

原HAL CPU写轨迹也已取得，可定位生产字段的指令。该轨迹只记录实际CPU写指令，标准libc provider中的 `uc.mem_write` 不在此mask内；不能把CPU写mask当作完整初始化mask。原始轨迹、输出和失败日志只私存。
