# 手机适配：原厂资料优先、增量验证

2026-10-23。用于后续手机硬件、固件、驱动和用户态适配；当前部署见[检查点](../../NEXT-SESSION.md)，有效边界见[操作规则](../../WORKING-BOUNDARIES.md)。

## 一轮最短闭环

1. 从检查点确定本轮缺口，只读相关功能和最近一次证据，不从头通读会话、归档和全硬件清单。
2. 找已有数据和实现；缺项再定向提取原厂固件或检索公开仓库。先恢复本轮需要的字段/函数，不以完整逆向整个HAL为前置条件。
3. 转换并接入一个可用改动，增量构建受影响目标；优先更新配置、软件包或可安全卸载的模块。涉及模块时保留实际内核ABI/依赖匹配，涉及IPA时保留核心/协议/签名匹配。
4. 做能判断问题的定向验证；通过后保留结果并继续下一缺口。失败先定位数据、实现、运行状态或验收脚本，按实际影响修正或回退。
5. 简记结果与下一步。部署/回退变化更新检查点，功能结论变化更新硬件清单；其它过程有一处可追溯记录即可。

## 数据获取优先级

| 顺序 | 来源与方法 | 使用方式 |
| --- | --- | --- |
| 1 | 私有输出目录、本机备份、已有原厂导出、固定提交和下载缓存 | 复用解析器与已核对数据；没有来源变化或损坏迹象就不重新下载、dump或读取EEPROM/NV |
| 2 | 同型号、同模组原厂ROM/OTA、vendor/odm、DTB/DTBO、XBL、固件、配置与库 | 先解包和静态分析，恢复板级连接、模式表、校准布局、参数及调用语义；需要时只读提取本机缺失文件 |
| 3 | 互联网公开仓库：官方内核、匹配版本CamX/CHI/schema、固件备份、device/vendor tree和已运行的同平台移植 | 搜索硬件ID、模组、芯片代际、文件名或符号，固定实际使用的提交/文件路径；缺文件可提取仓库中固件，缺语义可结合反编译恢复 |
| 4 | 近机型/同SoC资料、缺失字段的局部逆向 | 用作候选依据，核对本机差异；只验证差异，不重做已确认的通用部分 |
| 5 | 本机受控测量与人工标定 | 补齐原厂缺失、无法迁移或实际效果有问题的部分；完整画质和可靠性验收按功能需要安排 |

来源只需记录获取位置/版本、相关文件哈希、提取方法及适用模组/模式；已有记录直接引用。新下载、传输异常或来源变化时校验相关文件，不每轮扫描全盘。

## 提取与接入要点

- 先解包、读结构/字符串/符号，再匹配schema、原厂解析器、公开源码与反汇编；算法恢复优先覆盖实际使用的完整函数及边界。已有原厂指令输出可缓存，之后仅在算法、输入域或ABI变化时更新对照。
- 板级接线进DT，寄存器和电源生命周期进驱动，算法进IPA/服务，机型与模式参数进配置/固件包。按当前可工作的接口接入，通用化、上游整理与完整发行打包可在功能稳定后集中完成。
- 原厂通用参数与本机个体校准分开。EEPROM/OTP布局、校验、模组供应商、端序、单位、位深、色域、裁剪和模式绑定确认后再应用相应数据；尚未确认的条目保留默认/旁路，其它已匹配条目继续接入。
- 文件名相同、传感器相同或SoC相同不足以证明可直接套用。前摄关闭的TMC/GTM等开关按已核对模式保持；他机个体数据只用于研究格式，不作为本机标定。

## 按改动选择验证

| 本轮改动 | 默认验证 | 何时扩大 |
| --- | --- | --- |
| 文档、导航 | 改动文件的链接、内容和差异 | 索引清单变动时更新索引；发布或镜像修复时做相应全量检查 |
| 解析器、换算或算法 | 受影响字段/函数与已有原件或缓存原厂输出对照，覆盖本轮边界 | 改变算法域、量化或架构相关实现时补相应对照 |
| 调校/模式配置 | 来源与模式匹配、加载路径、相关实际输出 | 改公共配置或共享算法时覆盖受影响模组/模式 |
| 用户态代码/IPA | 受影响目标构建、协议/签名及相关应用路径；检查停流与资源回收 | 更改公共IPC/缓冲/生命周期时扩展相关进程模式及消费者 |
| 内核模块/DT/固件 | 构建及加载匹配、目标功能、相关错误和释放 | 更改共享电源/DMA/复位/启动链时补受影响共享设备及恢复路径；需要时重启 |

帧数与持续时间按启动、收敛和本轮缺陷选择，不把历史的测试规模当最低要求。同一相关载荷与运行前提已通过的案例直接引用；换传感器、模式、配置或关键状态不能跨范围冒认通过。修订计数/报告优先重新审计原始日志和样本；采集失败、载荷错误或状态不明才重新采集、修复或回退。
